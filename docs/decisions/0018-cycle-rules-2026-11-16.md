# ADR-0018: Cycle continues from TP; SL retries the losing trade; SL optional

- **Status:** Accepted
- **Date:** 2026-11-16
- **Spec refs:** CLAUDE.md §3, §4.1, §4.3, §4.4, §12

## Context
On 2026-11-16 the client explained the cycle again and changed three rules:

1. *"Entry 4000, TP 4003. When the trade hits TP it closes and the new order opens. Its starting point is the
   previous order's TP (4003) and its SL is 4000, the previous entry."* So the next trade opens at the TP whatever
   the gap is, and its SL sits at the previous entry. Q1 (wait for a pullback) no longer applies. Q2 is answered:
   previous entry.
2. *"The gap is needed when an SL hits. It decides where the new trade starts. With no gap, start again where the
   trade started (4000, SL hit at 3997 → new trade at 4000)."* This replaces the earlier confirmed rule
   "SL hit → bot stops".
3. *"SL is not necessary in a cycle."* `sl_points` is optional in CYCLE mode.

For loss protection after an SL, the trader chose the existing limits only: stop price, max cycles, daily loss limit
and manual stop.

## Decision
- **After TP:** next entry = the closed trade's TP, opened at market at once. `prev_entry` = the closed trade's entry.
- **SL of a cycle:** `sl_mode="previous_entry"` is now the default. It falls back to `sl_points` when there is no
  previous entry on the losing side, and to no SL when `sl_points` is blank. `"points"` stays as an option.
- **After SL (CYCLE):** re-entry = losing entry + sign·gap (blank gap = 0). The bot arms a touch trigger there and
  waits. `prev_entry` is **not** advanced, so a blank-gap retry is the same trade (same entry, TP and SL).
  The bot does not stop. The stop-price check on the next entry still applies.
- **No SL:** `None` in levels and the engine, `0.0` at the broker (MT5 convention) and in the journal. The UI shows "—".
- `gap_entry_mode` (Q1) is removed. Old saved configs that still contain it are read fine, because pydantic ignores
  extra keys. The browser form store key was bumped to `goldcycle.form.v2`, so the new SL default is not hidden by an
  old saved form.
- SINGLE mode is unchanged: SL is still required, and it ends in IDLE on TP or SL.

## Q6: gap direction after an SL (confirmed 2026-11-16)
The gap moves the re-entry **in the selected trade direction**: BUY 4000 → 4002, SELL 4000 → 3998. This is the
same formula the client's first sheet used for the gap.

## Alternatives considered
- Keep "SL → stop" and use the gap only on TP: contradicts the client's 2026-11-16 explanation.
- Add a "max SL hits in a row" limit: offered; the trader chose existing limits only.

## Consequences
- An SL no longer ends a session. In a market that keeps moving against the trade, the bot keeps retrying until
  stop price, max cycles, the daily loss limit or a manual stop. A trader running live should set at least one of
  these.
- With no SL, C1 can carry an open loss with no broker-side protection until TP, stop price or the daily loss limit.
- ADR-0001: Q1 and Q2 are resolved here. ADR-0007: "CYCLE SL → STOPPED" is superseded.
